# CSE-PCIDSS-POLICY-NO-INCIDENT-RESPONSE-010

**No Incident Response Plan**

## Signal Overview

| Field           | Value                                    |
|-----------------|------------------------------------------|
| Identifier      | `CSE-PCIDSS-POLICY-NO-INCIDENT-RESPONSE-010` |
| Domain          | PCIDSS                                   |
| Category        | POLICY                                   |
| Status          | Active                                   |
| Introduced In   | 1.0.0                                    |

## Description

No incident response plan for security incidents affecting the CDE.

## Applicability

This signal applies to:

- Organizations processing, storing, or transmitting cardholder data
- Security and compliance teams
- Human resources and training departments
- Third-party service providers (TPSPs)
- Incident response teams

## PCI DSS Context (Informative)

**Requirement:** 12.10 - Suspected and confirmed security incidents that could impact the cardholder data environment are responded to immediately

**Sub-Requirement:** 12.10.1, 12.10.2

**Regulatory Text:** "An incident response plan exists and is ready to be activated in the event of a suspected or confirmed security incident. The incident response plan is reviewed and tested at least once every 12 months. The plan includes at a minimum: Roles, responsibilities, and communication strategies, incident response procedures, business recovery procedures, data backup processes, and analysis of legal requirements for reporting compromises."

These references are informative and do not constitute compliance guidance.

## Notes

Detection guidance: Verify existence of documented incident response plan covering detection, containment, analysis, recovery, and post-incident activities. Monitor for annual plan reviews, testing exercises, incident response team training, and 24/7 incident response availability. Check for incident logging and evidence retention procedures.
